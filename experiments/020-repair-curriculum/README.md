## 已完成的诊断

- [数值复盘](diagnosis/019-numeric/)：修复只占六分之一更新，但占约 42.2% 监督 token；不能把问题简单归结为修复 token 太少。原示范在第 3 次调用修复，缺少未编辑进度提醒及失败后纠错状态。
- [命令级核查](diagnosis/019-trace-review.json)：高学习率的六道退步没有工具格式错误，实际出现空读取、失败补丁、无效果补丁和重复探测。低学习率的两道退步分别涉及错误实现后无效重试，以及 `sed` 替换中的 `&` 扩展导致源码损坏。
- “没有观察到源码修改”不等于“没有尝试修改”。这些是执行层面的观测，不能证明某一种 SFT 退步机制。原始命令、源码差异和开发题答案保持私有，不能用于训练。
- [本地动作长度检查](diagnosis/static-target-lengths.json)：55 道训练题的最长目标为 411 tokens，低于 512 上限；[tokenizer 身份](diagnosis/static-tokenizer-identity.json)已核对固定版本元数据。这没有执行真实任务，也没有检查包含完整工具输出的上下文，不能替代 Linux 准入。

两组都采用实际源码定位和带唯一匹配断言的 Python 字面替换，避免直接猜测行号以及 shell 替换扩展。候选只在最后 55 个样本位置改变上下文与必要的纠正目标：预定 28 个匹配断言失败、27 个错误修改后的测试失败。错误操作只是上下文，不能成为监督目标。每条保留修复都必须经过独立工作区判分；失败状态也需有实际执行证据。

这里比较的是相同更新次数和上限预算，实际输入、监督 token 与卡时分别报告，不宣称严格等 token 或等 FLOPs。开发集已多次被观察，其成绩只能用于选择；后续独立验收依赖只在开发阶段合格后打开的最终任务。
