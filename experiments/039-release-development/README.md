# 039 · 27B 参数独立开发筛查

在相同底座、前缀证据和执行预算下，比较原始 031 LoRA 与基础权重。031 在较早的构造题上净增 5 个百分点，随后用真实历史题评测时相对底座缺少净优势。此次固定 [038 的旧前缀流程](../038-independent-compact/results/2026-11-20/) 后独立比较参数收益。

- 六个新仓库家族各十道普通功能修复题，Python 和 JavaScript 各三十道。入选要求原父版本连续两次出现语义失败、参考修复连续两次通过、保护评分器通过。入选顺序由任务哈希确定。确认来源与原项目训练和已使用开发仓库家族隔离后，固定源码、测试、回退日志和运行顺序。
- 每题每组跑三遍，360 次任务执行。两组使用同一冻结的测试输出和 tokenizer 开场，逐区块交替先后。每题最多 12 次调用、6,144 生成 token 和 600 秒，每次生成 512 token、输入 8,192 token。评分要求预算内修复源码、通过独立副本重跑并显式提交。
- date-fns 的上游测试依赖另建离线环境。该依赖树含解析器依赖，Acorn 评测使用剔除该解析器包的环境。每道题的两个权重组使用相同的文件和执行环境。
- 开发晋级要求相对底座至少 +10 个百分点、按家族和任务配对的 bootstrap 区间下界大于零、单个家族下降至多 10 个百分点，以及完整请求、参数和评分审计。三轮复跑计入稳定性和成本，独立任务数为 60。底座预训练的来源无法据此排除。

CPU 准入完成。135 个候选中 107 个通过，按预定哈希顺序抽取 60 道，其中 9 道具有逐文件反转确认的多文件修复。工作站检查以新副本完成，保留最初因归档元数据、测试依赖或运行时兼容性导致的失败记录。原 031 的权重及 1,006 条训练输入已经核对，五份主许可证与固定上游版本逐字节一致，来源分发资格仍需发布审查。通过开发门槛后才开启单独封存的最终测试。发布范围与下载、验哈希、加载要求见 [ModelScope 发布目标](../../docs/modelscope-release.md)。
