# 036 · 把公开失败输出交给模型

[035](../035-edit-bottleneck/) 发现一句进度提示未能带动原本全程未改码的 12 道题。对这 12 道逐题核对发现，原始底座在前四次调用中都成功执行过指向可改源码文件的查阅形态命令，12 道最终都用完调用预算，且没有原样执行指定回归命令。命令形态与路径匹配描述可观察行为。由此检验具体失败证据能否帮助模型从查阅转到修改。

**固定对照。** 在每道历史开发题的全新缺陷副本里，只运行一次指定公开回归。两组都收到同一个退出码和测试后续说明。实验组额外收到按原有反馈规则规范化和截断的原始输出。每组另起同样的缺陷工作区，采用同一底座权重、推理设置、任务、工具与保护评分。共享公开测试的耗时单独报告，模型的 12 次调用、6,144 个生成 token、8,192 个单次输入 token 和 600 秒上限保持相同。

**CPU 准入。** 20 道均在本次前置检查返回预期的公开回归失败，原有文件内容保持一致。只执行模型已经可以调用的公开命令。报告记录实际输出中的失败标记和被截断的数量。模型首次输入从独立的同一份回执构造，两组只改变是否包含输出段落。

**验收。** 按题相邻运行两组，交替谁先跑。主要分数为预算内通过独立重跑且显式提交。预设值得用新仓库复验的门槛为净增至少两道、至少两个仓库家族有正净变化、最多一道退步。首次改码和历史 12 道的变化是次要诊断。这批题已经用于 034 和 035，当前结果用于开发决策。最终测试封存。

## 工作站重启后的恢复

工作站重启时已有 15 对完整结果。原运行目录与中断轨迹保留，30 次已完成评估及 332 次生成按原回执校验。第 16 题的第一个评估停在第 12 次生成。该次请求有提交记录但没有完成回执，从已保存历史重算的请求哈希吻合，实际新增 token 数未知。中断尝试已确认的 829 个生成 token 和 35,542 个输入 token 单独计入物理成本。

[恢复协议](recovery-plan.json)固定从第 16 题开始的 10 次未计分运行、原截止时间和全部预算。使用新工作区与同版本底座重新加载。保留并采用所有重启前的完整配对，将中断尝试排除在成功率分母之外。


## 结果

两组均修复并提交 3／20，道题得失为新增 2 道、退步 2 道。收益只出现在 Ramda，在 Arrow 和 D3 Array 则各退步一道。原来全程未改码的 12 道中，失败输出组比仅退出码组多改动一道，最终成功均为 1／12。完整对照未达预注册的复验门槛。[结果、首次改码曲线与匿名逐题数据](results/2026-11-20/)。
