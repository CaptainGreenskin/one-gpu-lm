# 043 · 首次改码和验证后提交的配对采集

从已审计的 025 训练轨迹恢复 133 个状态。22 个状态位于首次读到待修源码之后，独立复跑可重现故障。111 个状态位于当前正确补丁首次通过单独回归测试之后，已用独立评分核验。各组从同一个源码快照和同一份可见历史继续。两组都从 12 次调用和 6,144 个生成 token 中扣除历史用量，每次允许生成至多 2,048 token。两组交替先跑，使用同一版本的模型和工具流程，分别关闭思考和启用低档思考。每次生成都保留可审计回执。 [预算与登记](design.json)

以独立评分通过、模型在预算内显式提交且最终源码已通过回归测试计为成功。配对样本的候选动作必须真实执行，分叉前的可见上下文、源码以及剩余调用和生成预算必须匹配。对于首次改码，胜出的动作须写出最终验证正确的补丁。对于验证后提交，胜出的动作须提交已验证的同一份源码。配对的另一组须在预算内未完成正确提交。两组都成功时记录用量差异。 [042 独立开发对照](../042-first-edit-sft/results/2026-11-21-development/)

训练数据与完整工具轨迹留在工作站。登记和结果仅包含公开代码、配对统计、匿名曲线和产物校验信息。后续模型仍需通过已登记的开发与发布门槛。 [发布流程](../../docs/modelscope-release.md)
