# 044 · 重放完整修复轨迹后微调

042 的独立开发对照中，底座完成 30/180 次任务，LoRA 完成 24/180 次。043 在训练题上采集了更多成功续跑，覆盖读取源码、修改、验证和提交。本轮检验在同样的推理预算下，加入这些完整动作序列能否提升真正修对且提交的概率。 [042 独立对照](../042-first-edit-sft/results/2026-11-21-development/) · [043 采集结果](../043-decision-state-collection/results/2026-11-22/)

从训练工作区恢复改码前的源码，用正式开发评测的提示和工具反馈重放。采集阶段被拦截的命令没有执行，重放时去掉该命令和拦截提示。实际执行的命令需要复现归一化工具输出及改码前后的源码哈希。只有仍能通过独立评分、完成回归与提交、且每个目标动作适配 512 token 上限的整段轨迹才进入候选。已出现在 031 训练数据的题目整段剔除。 [设计与预算](design.json)

从固定版本的 Qwen3.8-27B 初始化 LoRA，沿用 031 的 BF16、rank 8、AdamW、学习率 1e-5 和种子 101。保留全部 1,006 条原训练记录及其相对顺序。每个梯度累积窗口最多加入一个动作，做完同样的 126 次优化器更新。新增输入和监督 token 单列。 [031 训练配方](../031-correction-mix/cycle-spec.json)

CPU 重放通过 20/21 条轨迹。一条因中间回复超预算剔除，通过的轨迹中有两道题已经出现在 031。去重后，新样本覆盖 5 个仓库家族和 18 道题，以 110 条动作训练。其中有 18 次实际改码、18 次独立运行回归、18 次提交。新增 8,060 个监督 token，单个新目标最长 244 token。 [冻结登记](registration.json)

训练审计通过后，在六个独立仓库家族的 60 道开发任务上对照底座和候选，每题三轮。两组使用同一评测流程，每题最多 12 次模型调用、每次 512 个生成 token、合计 6,144 个生成 token。验收需要完整配对、至少 10 个百分点的成功率提升、配对 95% 区间下界大于零，各仓库家族下降至多 10 个百分点。通过后才读取封存的最终测试。 [开发验收协议](../039-release-development/design.json)

运行入口需要已审计的 031 训练数据、043 轨迹和独立开发集清单。用 `freeze --collection <043工作目录> --development-cohort <独立开发集清单>` 生成私有训练登记，用 `train --publication <训练登记公开核验回执>` 训练，最后用 `audit --publication <训练登记公开核验回执>` 校验所有训练记录和权重重载。各命令通过 `python -m one_gpu_lm.verified.recovery_sft --root <工作目录>` 调用。 [复现入口](run.py)
