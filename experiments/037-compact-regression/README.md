# 037 · 提取关键失败输出

[036](../036-regression-evidence/) 中，给模型看按 2,400 字符截断的公开测试输出，没有提高同一批开发题的修复率。11 份原始输出被截断。037 检验同样的输出中，优先保留测试名、失败原文和位置，能否带来更多有验证的修复。

从保存的 20 份可见回归输出构造两种开场。对照组重跑原来的规范化前缀，实验组从完整输出中按固定顺序摘取最多四个 pytest 或 TAP 失败块。每块优先测试名、失败原文、位置，剩余空间保留少量差异行。每种字段和整段都有字符上限，实验组上限 1,200 字符。过长字段标为省略。未识别或没有错误正文的输出沿用原格式。摘录不调用模型，也不改断言，不读取评分用工作区。

CPU 预检覆盖 10 份 pytest 和 10 份 TAP 输出。候选在 5 道题中保留了原前缀没有包含的 10 条失败原文。两组使用原来的模型、调用预算、工具、反馈规则和独立评分，仅改变开场的失败输出内容与长度。编译、选项、测试命令和任务文件均沿用 036。两组均同期运行，按题相邻，交替先后。20 道题已用于前序开发诊断。最终测试封存。

主要分数仍为 12 次模型调用、6,144 个生成 token、单次 8,192 个输入 token 和 600 秒内，修复通过独立评分且显式提交。净增至少 2 道、至少 2 个仓库家族净增、最多 1 道退步才进入独立开发复验。报告另外保留被旧格式截断和找回失败行的固定子组，以及输入开销和首次修改曲线。
