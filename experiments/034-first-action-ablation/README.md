# 034 · 首步回归动作的损失权重对照

[033](../033-first-edit-probe/) 发现，032 在 108 次开发运行中的第一步都原样执行指定回归命令。032 新增训练数据中有 40 条对应的首步监督目标。034 检验的是一个更窄的问题：只去掉这些首步目标的梯度，是否会改变开场动作、首次修改时点和最终修复率？

两组从 032 的同一底座重新初始化 LoRA，沿用 BF16、SDPA、种子 101、梯度累积窗口及其实际记录数分母。逐组执行同一批 1,238 条样本和 155 次更新。`control` 的所有记录权重为 1，`masked` 的指定 40 条记录权重为 0。两组保留相同的输入、历史、标签、采样位置和前向及反向调用。指定目标共有 1,280 个监督 token，实验组由 92,897 个可贡献梯度的目标 token 降至 91,617 个。实验设计的可复核输入指纹和顺序见 [训练预注册](training-plan.json)。

[训练器差异](trainer.patch) 适用于哈希固定的 032 训练器。[执行入口](train.py) 在原训练工作区从冻结版本生成独立执行模块，核对公开预注册回执后顺序运行。每组保存实际输入和标签指纹、初始化 LoRA 指纹、逐条原始损失与权重、更新和硬件采样，以及私有适配器的保存重载校验。对照组使用完整 032 监督目标，历史成品只用来核对输入和训练口径。

两组完成后，用未出现在既有项目数据和评测中的仓库家族建立新开发集。题目先通过父版本失败、参考修复通过的 CPU 检查，再冻结运行顺序和每题预算。主要指标是预算内通过独立重跑并显式提交。辅助记录原样运行指定回归命令、无修改、首次实际修改和修对未提交。一次训练种子的比较用于发现机制和筛选后续改动。最终测试保持封存，参数保留私有。
