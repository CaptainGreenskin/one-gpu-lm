# 024 · 测试耗时与动作稳定性

固定底座、020 recovery、022 action，不训练、不选择发布模型，最终 72 题继续封存。本次只比较工具反馈边界：`baseline` 是 023 原样的 `metadata_v1`，`extended` 在此基础上处理额外测试耗时。不能把两个条件叫作原始反馈与规范化反馈；它们都已有日期/JavaScript 汇总耗时规则。

先用 023 已保存的全部 2,626 条工具反馈做 CPU 转换核验，证明 baseline 与旧规则逐字节一致、extended 不会读到原先截断的尾部，再冻结代码、数据、权重、顺序和规则，公开核验后才运行 024。历史反馈核验不是 024 评分，也不用于挑选 024 的有利轮次。

新增规则只处理完整行：pytest 汇总中 `in` 后的秒数（含 subtests 汇总及可选时分秒展示）、unittest 的 `Ran N tests in ...s` 耗时统一为 `0s`；AVA 风格测试状态行末可选的 `(Nms)` / `(Ns)` 耗时后缀移除，因此有后缀与无后缀的同一测试行可以一致。测试名称、状态、数量、顺序、文件名、断言、异常和返回码不改；任意日期、数字、PID、地址、未匹配的日志不处理。先保留原始 2400 字符前缀，再用旧规则，最后应用只缩短文本的新规则。截断处不完整的最后一行不应用新增规则。原始/实际交付反馈私有留档，独立判分始终接收原始输出。

这是受限的行模式识别，无法区分恰好同形的源码字符串与真实 reporter 行，不是通用语义解析器或安全边界。AVA 的并发输出顺序可能仍然变化，本轮不排序、不删除测试记录，也不在途中扩充规则。

沿用 15 道开发题、4 个仓库、3 轮、3 模型与 2 条件，共 270 次任务。每个模型/轮次加载一次，按拉丁顺序轮换模型；逐题相邻配对、交替条件先后，每题从独立缺陷副本开始。上限仍为 12 次模型调用、8192 输入 token/次、512 输出 token/次、6144 总输出 token/题、900 秒/题；工具 60 秒/次、2400 字符前缀。greedy、SDPA、seed 101 和已有确定性设置不变。完整顺序在 protocol.json 冻结。

每次加载对两个已使用的开发题初始请求各生成两次，共 36 个固定探针，不执行其命令、不计入任务分数。这些探针检查相同输入在同次/跨次加载的输出 token 是否变化。实际任务的相同输入 token 哈希分组也提前注册，与探针分开统计。

主要指标同时关注过程和结果：每个模型/条件的 45 个跨轮任务配对中，执行动作序列不一致数、成败不一致数，以及 15 题中各自发生变化的题数。动作序列包含每次工具命令哈希和所在模型调用位置。另报告三轮通过数、首次编辑、未编辑失败、首次轨迹分叉、135 个同轮条件配对、实际耗时/token、变换覆盖和硬件记录。输入、动作和判分分开解释，不把第一处反馈差异认作最终成败的唯一原因。稳定的失败仍然是失败。

总模型流程上限 16 小时，含加载、加载后控制、36 探针和 270 次任务。保存所有失败和未完成项，不补跑已完成任务、不挑选有利轮次、不延长截止；配对缺失须公开分母。只有 15 道重复使用的开发题及 3 轮，不能证明通用编码能力或所有未来输入确定。任何分数都不触发本轮最终测试或参数发布。
