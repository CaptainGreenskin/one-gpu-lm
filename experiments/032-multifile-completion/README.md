## 新数据与对照原则

- 用上游真实历史提交、父版本和测试构建修复任务，不把两个无关的手工错误拼成多文件任务。
- 参考修复前必须复现语义失败，参考修复后必须通过；再逐文件撤回修复，只有至少两个实现文件的撤回都导致测试失败，才计为本轮的“多文件”样本。注释、文档、类型标注或顺手格式化不凑文件数。
- Python 回归范围由提交触及的测试函数和按固定哈希选择的保留行为测试组成；无法静态定位到测试函数时保留整个模块。参数化用例完整保留，不修改断言或依据模型结果筛选。JavaScript 保留选定上游测试模块。缺少插件、固定版本子模块或构建元数据属于环境准备问题，不能当成模型失败或修复成功。
- 新增训练示范允许由已审查的上游参考补丁构造，但每条动作必须真实执行。明确标注 `upstream_reference_guided`，不计作教师自主完成率或失败后自主纠错轨迹。任务、测试、许可证和贡献者声明保留来源。模型不能在工具环境中读取参考修复、Git 历史、其他任务或训练权重。
- 示范包含失败复现、聚焦读取、源码修改、单独验证以及显式提交；提交必须发生在共同预算之内。没有验证、超长、超预算的样本整段拒绝，不截断目标、不补造成功输出。
- 031 的原始完整轨迹与失败状态片段保持各自来源；新增参考指导示范另列。只训练一个候选，不根据开发成绩调混合比例或挑检查点。
- 新开发仓库与训练、已有开发及其他已使用仓库来源隔离。排除清单只读公开来源清单，不读取封存测试题。每道新开发任务对底座、031、032 使用同一源码、测试、工具环境、调用与 token 预算。
- 同时报告修复正确率、正确且显式提交率、最终源码独立验证状态、无修改率、第一次修改位置、各仓库配对差异、重复稳定性，以及全部训练和评测成本。
