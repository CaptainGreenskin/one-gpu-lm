# 035 · 为什么模型看了代码却迟迟不改

[034](../034-first-action-ablation/) 的两组 LoRA 一共 31 次用完调用预算仍未修改源码。屏蔽首步回归动作的监督目标减少了原样运行回归命令的次数，修复并提交仍很少。

本轮第一阶段补齐 **27B 原始底座**。沿用 034 的 20 道开发题、四个仓库家族、任务顺序、可见工具、独立评分和推理格式。每题上限为 12 次调用、每次生成 512 tokens、全题生成 6,144 tokens、每次输入 8,192 tokens、600 秒。每题一次，与 034 已有两组结果按匿名题号配对。用原始回执复算输入 token、执行动作和保护环境评分。评分以在预算内通过独立重跑且显式提交为准。

诊断对照统计首次源码变更之前的实际动作。查看形态使用现有保守语法分类，同时记录工具非零退出、相同命令在相同源码与反馈下的重复、格式失败、反馈截断、上下文裁剪及单次生成上限。动作形态只能描述观察到的行为。这批题也供提出下一阶段的单一改动，后续结果按开发对照解释。

[底座预注册](baseline-plan.json) 固定 034 的既有证据与本次运行规则。最终测试封存。公开报告只包含匿名指标、曲线、审计和复现代码。模型和任务保存在私有目录。

## 底座对照

底座与两组 LoRA 的修复且提交数分别为 1、1、0，全程未改源码的题数为 12、15、16。合计 43 条未改码轨迹都耗尽 12 次调用。其中 39 条至少一半调用为查阅形态，5 条出现同命令、同源码与同反馈的重复，5 条发生上下文裁剪。[审计、逐题数据和曲线](results/2026-11-19-baseline/)。

## 一次性提示对照

[第二阶段预注册](reminder-plan.json)固定唯一干预。仅第 5 次请求有机会增加提示，条件为前四次没有改源码，且至少三次成功执行查阅形态命令。提示要求从已有证据出发尝试最小修复，同时为验证与提交留出调用。已归档底座的 20 条轨迹中，15 条符合触发条件，其中 9 条最终全程未改码。沿用底座权重、任务顺序、预算、工具、评分和上下文裁剪，提示 token 计入每次输入上限。

每道题新增一次提示组运行，并与已审计的底座对应结果匹配。保留未触发题和全部退步，单独统计同等提示条件下已经发生的输入、工具反馈或生成差异。复验门槛要求修复且提交净增至少 2 道、至少 2 个仓库家族有正收益、最多 1 道退步，并且在触发前历史匹配且实际触发的题中也至少净增 2 道。题目已用于诊断，因此这一步衡量开发侧信号。
