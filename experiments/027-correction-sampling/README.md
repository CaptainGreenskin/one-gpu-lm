# 027：采集经过失败验证的纠错示范

**阶段：8 道训练失败题已复盘，首次采集协议已固定，尚无 027 模型采集结果。** 026 的 21 条合格接手轨迹都只有一次源码修改；本阶段检验是否能自然得到“修改后失败，再修改后成功”的示范。采集过关后才进入新的候选训练阶段，最终测试继续封存。

## 先看失败记录

[只读诊断](preparation/diagnosis.json)核对 026 中双方都失败的 8 道训练题、16 条已审计轨迹，没有新增模型调用：

| 训练任务 | 观察到的失败行为 | 对采集规则的启发 |
|---|---|---|
| underscore-difference-polarity | 两边都持续查阅相关实现，没有修改 | 提醒检查是否已有足够证据动手，不要求为了满足流程而随意修改 |
| underscore-partial-dynamic-context | 两边围绕模块入口查阅，耗尽调用未修改 | 提醒保留修改、测试和纠错预算 |
| ini-nested-section-boundary | 已出现失败反馈和异常输出，仍继续探测；复合命令的最终退出码为 0 | 修改后要求单独运行声明的回归命令，避免把外层 shell 成功当成测试通过 |
| humanize-intcomma-string-groups | 学生重复同一探测；教师 8 次生成达到 512 token 上限且工具格式不完整 | 提醒命令简短、避免相同状态下重复命令；仍计入所有失败调用成本 |
| isodate-duration-fraction-components | 两边未修改，教师 4 次达到生成上限且工具格式不完整 | 不将不完整或未执行的调用作为正向训练目标 |
| humanize-delta-negative | 教师第 10 次才修改，测试失败后剩余两次仍是探测 | 在足够证据下尽早动手，为真实失败后的修正保留预算 |
| inflection-camelize-lower-first | 学生修改 3 次、教师修改 4 次，仍未修对 | 多次修改不自动等于高质量示范，必须最终通过独立判分 |
| inflection-humanize-id-anchor | 学生第 11 次才修改；教师修改 3 次仍失败 | 保留失败修改和反馈作为上下文，只监督最终成功纠正 |

这里有 5 题双方都没有改源码，另 3 题至少一边修改过。12 次修改动作都发生在非零退出的复合命令中；按“单独回归命令”口径，修改后单独失败检查数为 0。这不表示模型从未看到测试失败：私有记录确实包含复合命令里的断言失败。不能用严格统计口径掩盖这类反馈，也不能据此认定环境有错或失败只有一个原因。

## 固定对照

使用同一个固定版本的 27B 底座教师，两边都从全新、相同的故障源码开始：

- **control**：原有工具格式、上下文管理和提交前单独验证规则。
- **correction**：增加通用纠错流程说明、基于可见历史的进度提醒，以及每次修改源码后必须先单独回归的约束。约束拒绝的请求仍计入预算，控制器不替模型调用测试，不提供正确补丁或隐藏检查反馈。

这是一组流程改动的整体对照，不能分辨提示语、提醒和强制检查各自的贡献。两个流程按题交替先后执行，固定顺序，失败不重试。测试通过后正常结束，不强迫第二次修改，不人为引入错误。

任务为上述 8 题，加上按固定哈希、仓库轮转选出的 24 道补充训练题；补充题排除全部 026 任务。两组都是训练侧数据，不冒充独立开发集，也不打开最终测试。任务可能曾被 025 的采集或训练使用。

每条路径最多 **18 次调用、每次生成 512 token、累计生成 9216 token、输入 8192 token、actor 900 秒**；每次工具 60 秒。共 64 条路径，物理调用总上限 1152 次、生成总上限 589824 token；整轮最多 6 小时，包含模型加载和独立判分。实际推理保留既有运行时的 512 token 上限。不能把本轮分数与 026 的 12 次调用结果当作同预算提升。

## 合格示范与门槛

必须同时满足：模型实际改过源码；在该修改状态上单独运行回归且真实失败；之后再次修改为不同源码；最终单独回归通过并显式提交；独立的新工作目录判分通过；所有受保护文件在每步都完整；请求、反馈、源码证据、预算和编码审计通过。超时、未修改的原始故障、拒绝执行、复合命令退出码、没有中间失败的两次修改均不能充数。源码哈希变化证明发生修改，不单独证明其语义价值。

只导出最后成功修改及其后实际执行的验证、提交等动作。较早失败动作保留在可见上下文，不作为正向标签；最后成功修改的真实输入中必须保留前面的错误修改和失败反馈。整条候选编码不完整就拒收，不截断训练目标。

执行前固定采集门槛：

1. 全部 64 条路径、32 组配对和物理成本审计通过。
2. correction 至少获得 **6 道不同任务**的合格示范，覆盖至少 **3 个训练来源家族**，其中至少 **3 道补充题**。
3. correction 的合格示范数比 control **净增至少 3 道**，独立判分成功总数不能净下降。

过关只意味着可以准备一次候选训练，不表示模型已经变好，更不是参数发布门槛。若通过，再固定混合数据、训练预算与开发集验收协议后训练唯一候选；若未通过，保留失败和全部成本，发布报告，不追加题目凑分，也不启动训练。训练与开发阶段不得使用最终测试。

## 复用与验证

源码在 `one_gpu_lm.verified.correction*`，9 项新增 CPU 测试覆盖真实失败链、相同预算、保护文件、未知请求成本、上下文丢失、错误目标排除和完整审计导出。[真实 Linux 沙箱检查](preparation/cpu-sandbox-check.json)使用脚本化小样例，模型调用为 0；它不计入采集成果。

执行前发布的 [execution-protocol.json](execution-protocol.json) 固定代码、模型、数据、顺序、预算和门槛；必须通过公开文件校验及 CI 才启动唯一一次运行。原始任务、源码、轨迹和参数保持私有；公开诊断、规则、安全指标、配对表、曲线和硬件记录。完整复现实验需要符合接口并获准使用的数据；公开数字可单独复算报告。
