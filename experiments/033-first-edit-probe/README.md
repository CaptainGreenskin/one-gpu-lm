# 033 · 同一段历史下的下一步动作

032 相对底座少了 13 次预算内修复并提交，涉及五道开发题。其中七次未改变源码，六次到第 11 或 12 次调用才首次修改。13 次退步都从相同输入 token 的第一个请求开始分叉。032 的 108 次首步均为原样调用指定回归命令，底座和 031 的首步均没有原样调用。这个计数不覆盖通过其他命令执行测试的情况。完整逐模型计数和配对位置见 [324 条开发轨迹的复盘](preparation.json)。

训练输入也出现同一方向的变化。031 保留的 118 个首步目标中，0 个原样调用指定回归命令。032 新增的 40 个参考指导首步目标中，40 个原样调用。全量训练目标共 1,238 条，按实际归档字节重新核对。[训练目标计数](training-target-review.json)。

033 用固定历史检验早期动作差异。五道退步题各选两段编辑前历史。一段来自底座实际成功运行中首次改源码前，另一段来自同一道题、同次重复、同一调用编号的 032，两个状态都没有改过源码。另外纳入四道在底座和 032 上均三次成功的控制题，取底座首次修改前的历史。每道题固定选择底座最早成功的重复。总计 14 段历史，三组权重各生成一次，共 42 次。

[冻结协议](protocol.json)固定原始请求哈希、输入 token 哈希、底座和 LoRA 身份、同一个关闭思考的生成配置。所有请求使用原有 8,192 输入 token 和 512 单次生成 token 上限。模型只看到当时归档的历史，评估器单独核对生成的命令文本是否等于该题曾执行过的首次修改命令。还记录原样回归命令、查阅形态、其余可解析动作和格式失败。没有实际执行生成的命令。未命中已观察修改命令时，其他可解析动作可能仍可修复，不能因文本不同判为失败。

结果回答的是在同一段历史下生成动作是否改变，以及 032 换成底座历史后是否更常给出曾经有效的第一次编辑。只用既有开发题做机制诊断，不把一次动作当作完整修复成绩，也不以此区分训练数据内容与额外更新步数。最终测试封存，模型参数保留私有。

## 结果与下一项检验

42 次生成全部通过独立核验，三个模型在每段历史上收到相同的输入 token。五道退步题使用底座的编辑前历史时，底座、031、032 分别命中已观察首次编辑命令 5／5、2／5、0／5。换成 032 的历史后三者都为 0／5，其中 032 五次都输出查阅形态的命令。两种历史含有此前不同的动作和工具反馈，无法把差异只归因于第一步跑测试。[逐题矩阵、结果与耗时](results/2026-11-19-next-action/)。

在四道原本稳定成功的控制题上，032 拿到底座历史也未输出相同的首次修改命令。它在自己的原轨迹中确实成功了。这说明命令文本匹配是一个诊断指标，其他可解析动作的修复效果还需要单独执行检验。

值得优先验证的是首步监督的作用。下一次配对训练可固定样本、历史、顺序、随机种子和更新数，只调整 40 条新增首步回归目标的损失权重。用另一批独立仓库和相同推理预算评估修复且提交，同时观察首步命令和首次实际修改时点。
