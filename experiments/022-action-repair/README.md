# 022 · 更早执行有依据的修复

021 的两道新增开发退步均用了 12 次合法工具调用却未修改源码。逐调用复盘见 [diagnosis.json](diagnosis.json)：一条轨迹先连续读文件，再运行通过管道隐藏了退出码的失败测试，最后继续探测；另一条连续读取不存在的构建产物。020 固定对照在同题分别于第 9、6 次调用执行编辑并测试。

这些是已观察开发任务的行为证据，不是单一原因的因果证明。开发题的提示、答案、源码、命令及输出均不作为训练数据。

本轮保留 020 recovery 每题五个原样样本，共 275 条，包括全部 55 条错误编辑后的纠错示范。只替换每题一个 `stall_repair` 槽位：先实际读取允许编辑的源码、执行声明的失败测试，再用一条短命令修改并执行相同测试。按训练仓库内排序交替分配，其中一组还先观察一次真实缺失文件错误；读取失败后立即回到允许编辑的源码。修复发生在第 3 或 4 次调用，总过程不超过 12 次调用。所有目标都经过实际执行及独立判分；`set -e` 保留编辑和测试失败的退出码。

保留完整上下文及目标，超过 4096 总 token 或 512 目标 token 的新样本保留原 020 槽位，不截断、不丢题。要求至少 40 个训练任务成功替换，每类至少 16 条，否则不训练。这个组合课程同时改变行动时机、缺失文件恢复和编辑后测试；不能把最终收益单独归因给其中某一项。

唯一候选从固定 Qwen/Qwen3.8-27B 底座初始化，LoRA rank 8、学习率 2e-6、seed 101，更新 330 次。底座、固定 020 recovery 和新候选各运行一次相同的 15 道开发题：每题最多 12 次模型调用，输入 8192 token，单次输出 512 token，总输出 6144 token。CPU 样本准备单独计时；模型流水线总预算仍为一次 12 小时。等上限不代表等实际训练 token 或等 FLOPs。

开发选择必须同时比底座和 020 净增至少 1 道，且分别最多 1 道退步；否则本轮最终测试不启动。通过后才运行 48 道历史回归与 021 原样继承、尚未模型评测的 24 道新仓库留出。参数发布还要求新留出净增至少 3 道、两组均零退步、9 个函数回归全过、格式失败率不增加及全部工程与来源检查通过。只发布合格的确切 LoRA 适配器，并注明底座版本；不把适配器当作完整 27B 权重。
