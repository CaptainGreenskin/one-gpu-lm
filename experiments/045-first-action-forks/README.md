# 045 · 同一状态分叉的首次动作采集

044 的六次退步集中在两道独立开发题，六次都没有进入改码。043 的低思考组在训练题上多完成了八次，但两组的解码设置贯穿整条轨迹。045 只改变第一次新回复的采样方式，观察两种动作各自能否带来通过独立测试并提交的完整修复。 [044 开发对照](../044-deployment-recovery-sft/results/2026-11-22-development/) · [043 采集结果](../043-decision-state-collection/results/2026-11-22/)

从 043 的 22 个首次改码前状态恢复源码和工具历史。先复现可见测试的失败，再复跑原有的一到两次调用并核对反馈和文件哈希。两组看到同一份历史，消耗相同的历史调用与 token 预算。首次新调用一组贪心解码，一组用固定种子采样，此后两组都用贪心解码。两组共用训练采集的提交校验，要求单独运行回归测试后再提交。正式开发对照沿用原有推理流程。 [冻结设计](design.json)

只有初始请求和源码相同、两组各自执行了不同的首个命令、完整修复结果出现分歧，而且两种目标都匹配同一个部署 tokenizer 前缀时，才生成一组偏好样本。每个状态保留两组运行记录，超时或受保护源码发生变更的轨迹不进入训练。原始请求、任务和样本留在私有工作区。 [采集与审计入口](run.py)
