# 028：从实际错误补丁状态接手

027 的纠错流程修好 26/32 道训练题，但只有 1 条合格多次纠错示范；25 道成功题只修改了一次。028 先验证能否从已有训练轨迹恢复足够多的真实错误补丁现场，再决定是否启动模型采集。最终测试继续封存。

**CPU 准入已通过，GPU 配对采集规则已冻结，尚无本轮模型采集结果。** 24 个候选全部重放核对；22 个仍会单独回归失败，去重后选出 9 道题、4 个来源家族。另 2 个候选单独回归通过，证明复合命令错误不能直接用作错误补丁证据。实际执行 218 条 CPU 命令，无新模型调用。[准入记录](preparation/admission.json)与[初始上下文检查](preparation/context-screen.json)公开，后者的 18 条分支均完整保留失败修改和反馈，初始输入最长 6348 token。

## 第一阶段：历史状态准入

只扫描 025 正式训练采集、026 训练接手、027 训练纠错这三轮已审计的 310 条轨迹；不读取开发或最终测试轨迹作为样本。初步只读盘点有 24 个“源码已修改且命令返回运行错误”的候选状态，涉及 11 道题、4 个来源家族。这个计数不是合格状态数：复合命令失败不证明补丁仍然错误。

执行前固定 [admission-protocol.json](admission-protocol.json)：

1. 每条历史轨迹按调用顺序扫描，保留每种源码状态第一次实际运行错误；排除原始故障、未执行请求、超时、输出限额错误、缺失源码及未审计记录。
2. 在新的离线沙箱里重放该调用之前的真实操作，逐步核对源码哈希、保护文件、退出状态与规范化后实际反馈。工具历史不重写，不取用后续修复或参考答案。
3. 对重建状态**重新单独执行声明的可见回归**。只有真实运行错误且源码和保护文件未改变，才确认该状态仍未修好。此检查属于新增 CPU 验证，会单独记账，不冒充原模型执行过的命令。
4. 依次按 025、026、027 的登记顺序选择每道题第一个确认状态，再按固定哈希、来源家族轮转，最多 12 道不同任务。选择不用历史轨迹未来是否成功作条件。
5. 至少确认 **6 道不同任务、3 个来源家族**，才允许准备后续 GPU 采集。若不足，发布所有准入和拒收结果，不增加题目、放宽复核条件或启动训练。

CPU 准入最多 30 分钟、1024 次实际工具执行，每条命令最多 60 秒；初步盘点的 24 个候选全部保留去向，无自动重试。新增模型调用、参数更新均为 0，隐藏判分不参与状态准入。

恢复出来的是“经过内容与反馈核对的历史前缀，再加一次当前可见回归确认”。它不等于保存了历史 inode、时钟和进程内存。未来两组会从同一份新快照开始，文件内容、权限、mtime 与完整可见历史相同。

## 第二阶段：固定接手对照

[execution-protocol.json](execution-protocol.json) 固定 9 个状态、快照哈希、代码、提示、预算与门槛。同一个固定版本的 27B 底座在相同状态上运行两种流程，按题交替先后，每条路径只跑一次：

- **control**：保留历史指令和可见操作记录，增加共用的接手预算与回归确认反馈，沿用提交前验证规则。
- **correction**：在同一历史基础上再添加通用纠错提示、进度反馈，并要求每次新修改后先单独回归。拒绝执行的请求也计入模型调用与 token 预算。

一份历史前缀来自 027 的纠错组，两条分支都会继承该前缀的旧指导语。因此对照测量的是“在相同已知历史上增加接手干预”的整体效果，不能把 control 称为完全没有纠错指导的模型，也不能拆分各提示的因果贡献。

每条路径最多 **12 次新调用、每次生成 512 token、累计生成 6144 token、输入 8192 token、600 秒 actor 时间**；每条工具命令最多 60 秒。18 条路径总上限 216 次调用、110592 个生成 token；整轮最多 3 小时，包含加载与独立判分。历史调用不消耗这份新增预算，也不冒充本轮新增物理成本。

必须发生新的源码修正，最终单独回归、显式提交和新工作目录独立判分均通过，并完整审计保护文件、状态、请求和成本。最后成功修改的实际输入必须仍保留真实历史失败修改及回归确认反馈。仅最后成功的新修改及其后实际执行的动作可作为正向目标；历史动作、之前的新失败修改只作上下文，不能截断目标凑样本。

模型运行前固定数据门槛：全部 18 条路径审计通过；correction 至少 6 道合格任务、3 个来源家族，至少 3 道不属于 027 已合格的唯一任务；合格示范总数及独立修复成功总数均不得低于 control。这里“超过 027 的任务覆盖”不等于新仓库或从未训练过的任务。任一条件未达成就发布完整结果，不启动候选训练，不追加采样。

采集通过也不代表模型已提升：之后还需冻结单候选训练和开发验收方案。最终测试、原始源码、工具轨迹和权重保持私有。当前 CPU 准入不授权自动发布参数。

## 实现与测试

`one_gpu_lm.verified.failure_states` 提供候选扫描、受限重放、可见回归确认和快照准入。8 项 CPU 单元测试覆盖真实失败链、复合命令假阳性、反馈变化、测试文件篡改、未来答案泄漏、原始故障/超时排除、确定性去重与执行预算。另 6 项接手测试覆盖同状态同预算、完整真实失败上下文、快照篡改、截断拒收、只监督最终正确修改，以及新旧成本分离的完整审计。
