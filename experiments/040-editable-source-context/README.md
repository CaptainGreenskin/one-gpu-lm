# 040 · 开场源码与首次改码

039 的双方共同失败 43 道题中，有 37 道题在两组各三轮中始终没有修改源码。在这 37 道题的每组 111 次运行中，底座有 33 次、031 有 36 次出现了成功且明确指向可编辑文件的查阅命令。该计数覆盖命令显式指向的路径。目录级搜索和间接查阅仍可能让模型看到源码。[039 审计结果](../039-release-development/results/2026-11-20/)

040 使用这批既有开发题的全部 60 道题，用单个固定的 27B 底座加载完成两组 120 次运行。对照组复现 039 的输入 token。实验组在同一开场后附上来自原始工作区的可编辑文件片段。选段按开场出现的标识符与源码行的匹配数定位，再记录原始行号。每题最多增加 1,536 个开场 token，开场上限为 4,096。片段从每文件 64 行开始，超限时依次使用 32、16、8 行。无片段可用的题保留在配对分母内。

每题的工具、回归命令、保护评分器、调用预算、推理配置及权重一致。相同题目相邻成对，交替先跑哪组。主要指标为预算内有效改码、通过保护重跑并完成提交。首次改码时点、改码后正确率、首次输入和累计 token、执行耗时为辅助诊断。复验门槛沿用 039 的 10 个百分点净增、家族和题目配对区间下界大于零及单家族下降至多 10 个百分点。[固定设计](design.json)

CPU 预检会绑定 039 完整审计、原始工作区哈希、两种开场 token 和运行顺序。开发复验仍需另一批独立仓库。最终测试集封存。源码片段、测试、工具命令和模型轨迹放在私有目录。[预检和运行入口](study.py) · [独立回放](audit.py) · [曲线和报告](report.py)
