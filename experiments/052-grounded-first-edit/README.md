# 052 · 首次修改的源码证据

051 的六组退步中有五组全程未改码。052 从已通过离线评分的 79 条训练示范重新采集，确保首次修改用到的源码确实出现在模型看到的工具反馈里。候选示范来自七个训练仓库家族，051 开发题与封存测试题继续独立。 [051 开发结果](../051-repair-closure-sft/results/2026-11-24-development/)

保留示范的首个已执行修改，重新在干净沙箱中读取它需要的原文或带行号的区间，再完成修改、回归、提交和独立评分。范围由已知参考修复确定，读取动作作为输入，监督信号仍只来自修改、回归和提交。原文必须在正常的工具反馈上限内完整可见。开发评测仍使用原始开场和同组预算。

训练数据沿用 050 的家族、示范数量和必要多文件门槛。通过后再冻结底座、训练配置和独立开发对照。公开记录仅包括聚合数量、匿名结果和曲线。 [采集规则](design.json)

通过采集门槛后，按 051 的 27B 底座和 BF16 LoRA 配方冻结了 287 个监督动作和 36 次参数更新。本轮可以检验这组示范是否提高任务通过率。要单独测量源码可见性的作用，需要让两个训练组使用同一批示范。

[采集结果与曲线](results/2026-11-24-collection/) · [训练登记](training-registration.json) · [训练结果与曲线](results/2026-11-24-training/)

在仓库根目录运行 `PYTHONPATH=. python experiments/052-grounded-first-edit/report.py experiments/052-grounded-first-edit/results/2026-11-24-training`，即可用公开测量重新生成训练曲线。绘图需要 Matplotlib。

开发对照用六个独立仓库家族的 60 道题，Python 和 JavaScript 各 30 道。每题做三组配对，底座和 LoRA 使用相同的首条工具反馈、调用和 token 预算。沿用 051 的通过率门槛。 [开发验收规则](development-design.json)
