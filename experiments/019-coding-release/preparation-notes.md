# 冻结前的数据验收修正

这些修正在 019 的任何模型评分或权重更新之前进行。原始验收记录和任务清单私下保留；最终协议将记录完成后的文件哈希。两个学习率、数据规模下限、调用与 token 预算、开发集选择规则及发布门槛保持不变。

- SemVer 的原始测试配置需要 `pytest-cov`，CSSSelect 的测试需要 `lxml`。为两个仓库单独复制测试依赖，固定增加 `pytest-cov==7.0.0`、`coverage==7.10.6`、`lxml==5.4.0`，没有改动旧实验的共享环境。
- Mocha 用失败测试数量作为非零退出码。验收现在核对实际输出中的失败数量与退出码，不能只接受退出码 1，也不能把任意非零退出当作有效测试失败。Python 的测试收集错误仍不满足本轮准入条件。
- 开发集的 `attrs-optional-validator` 原始缺失实现会在模块导入时触发异常，阻止测试收集。冻结前改为同一函数漏做校验的缺陷，保留仓库版本、函数、测试命令与开发集分区。其余开发任务沿用原定义；这一项不再是与 014 完全相同的缺陷，不能声称开发集逐题完全复刻 014。
- 初次新仓库参考实现扫描中，Schedule、Backoff、Addict 通过。CSSSelect 命中 `lxml` 的相关封装和缓存文件。已阅读该封装，并为 CSSSelect 准备移除这两个文件的独立依赖副本；原文件与哈希保留在不可见的私有隔离目录。最终验收必须在该环境中重新扫描并通过测试，不能把初次命中直接改记为通过。
- 训练任务若发生收集错误或无法构成有效的测试失败，只能在冻结前按执行证据排除，保留原因，并继续满足至少 48 个任务、4 个训练仓库等原有下限。不得根据模型成绩换题。

此文记录准备阶段的修正，不能替代最终数据准入、执行示范、训练结果或参数发布验收。
