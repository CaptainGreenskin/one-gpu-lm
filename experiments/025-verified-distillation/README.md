# 025：从实际执行轨迹到可验证的编码改进

本阶段先回答一个范围有限的问题：现有 27B 底座增加修复调用预算后，能否产生值得学习的完整成功轨迹？先验证采集方法，再投入 100～300 条轨迹和一轮学生训练。完整目标见[阶段目标](../../plans/verified-coding-cycle.json)。

**当前状态：CPU 环境准入完成，教师试跑规则预登记；尚无本轮模型生成或训练结果。** 本页不是“模型已变强”的结论。后续按“底座/蒸馏参数 × 当前/改进执行流程”分开测量收益，至少 60 道开发任务、6 个独立仓库家族和两种语言；完整对照的计分与预算将在新开发评分前另行冻结。

## 先做有上限的训练数据试跑

唯一教师为本地已有的 `Qwen/Qwen3.8-27B`，精确版本与许可证见 [teacher-profile.json](teacher-profile.json) 和 [原始模型许可](notices/Qwen3.8-27B-LICENSE.txt)。加载 BF16、SDPA、贪心生成，关闭 thinking，不加载适配器，不购买外部教师服务。这是**同一底座的高预算自蒸馏可行性试跑**，没有声称教师比底座更强，也没有把单条贪心轨迹称为搜索。

冻结输入、题目顺序、预算和准入条件见 [pilot-protocol.json](pilot-protocol.json)。一题只尝试一次，不按成绩重跑，不丢弃失败。预算如下：

| 项目 | 上限或规则 |
| --- | --- |
| 任务 | 12 道，仅训练分区；3 仓库，每仓库 4 道 |
| 每题模型调用 | 24 次；每次最多生成 512 token；总生成最多 12,288 token |
| 输入 | 最多 8,192 token；使用已有完整轮次压缩规则 |
| 工具 | 每条最多 60 秒；返回反馈最多 2,400 字符；使用 024 extended 规范化 |
| 单题 | 动作采集最多 900 秒；独立判分另记，最多 60 秒命令预算 |
| 整次流程 | 最多 4 小时，包括权重核验、加载、采集和判分；不足下一题预留时间时停止 |
| 故障 | 后端未知在途调用停止整次试跑，保留未知成本，不自动重发 |

“合格完整轨迹”须同时满足：实际模型生成并执行；源码发生修改；未篡改可见测试等受保护文件；在最终源码状态上单独运行规定验证命令并通过；明确提交；新建工作区内的独立隐藏检查通过。仅恢复参考源码的 CPU 检查、单条动作记录、模型自称成功均不计入。

试跑可行性门槛：全部 12 题单次尝试完成，至少 6 条合格完整轨迹，每个仓库至少 1 条且覆盖两种语言；每个已执行请求的实际 tokenizer 输入及生成 token 记录可重建；合格轨迹中有效动作均能在 8,192 token 编码筛查上限内完整保留监督目标，至少覆盖修改、验证、提交。失败动作保留在历史中，格式错误输出不作为正例监督目标。不允许截断目标后仍计为合格数据。该长度筛查不等于已选定学生训练配方。

**通过此门槛只允许进入扩充数据与学生配方准备。** 它不允许声称模型能力提高，不触发权重发布。数据目标仍是 100～300 条完整执行轨迹，必须另外报告唯一任务数与动作训练记录数。

## 任务、来源与隔离

首批训练任务是在以下精确版本上构造语义故障，并编写可见回归和独立隐藏用例；不是历史 issue，也不是外部标准基准：

- [python-humanize/humanize](https://github.com/python-humanize/humanize/tree/a95004512dde4e8f0269946bb4af754382347441)：Python，保留 MIT 和声明借用的 Django BSD 通知。
- [gweis/isodate](https://github.com/gweis/isodate/tree/17cb25eb7bc3556a68f3f7b241313e9bb8b23760)：Python，保留 BSD 和声明借用的 Python 文档许可。
- [npm/ini](https://github.com/npm/ini/tree/3c96c74fd42584bd655e17a4e63e2ef0a3b406ee)：JavaScript，保留 ISC 通知。

[来源清单](pilot-sources.json)记录原始文件摘要、版本元数据改动、关联仓库家族和审核范围。当前审核范围是私有训练任务执行及内部轨迹 SFT；未据此批准原始源码、轨迹或模型权重再发布。原始任务、隐藏用例、参考源码和轨迹留在私有工作区，公开数字与摘要回执。

任务仅挂载经文件清单核验的源码子集与只读运行时。Linux `bubblewrap` 隔离网络与宿主目录，不挂载宿主 `/usr`、home、pip、模型、原版源码或参考修复。Python 3.12.16 与 Node 24.22.2 的准入证据见 [runtime.json](preparation/runtime.json) 和 [隔离检查](preparation/isolation.json)。这仍是单用户实验环境，不是恶意多租户沙箱。

CPU 准入要求：原版通过可见及隐藏检查；故障版分别在可见、隐藏检查中语义失败；恢复参考文件后通过独立判分。全部 12 题已通过，[最终身份绑定回执](preparation/admission-003.json)记录 0 次模型生成。早期上传、运行时构建和 CPU 执行中断也保留在[准备尝试说明](preparation/attempts.json)，不计为模型失败或教师数据。

## 在自己的任务上复用

公共实现位于 [`one_gpu_lm/verified`](../../one_gpu_lm/verified/)：

1. `tasks.py` 核验精确来源和许可确认字段，阻止训练/开发仓库家族交叉，按唯一锚点构造故障，复制允许修改的源码到独立判分区。
2. `sandbox.py` 验证运行时所有文件及分组挂载目录，执行有预算的离线命令；不要把宿主包目录整体挂载进去。
3. `admit.py` 执行 CPU 准入。输入 `sources.json`、`tasks.json`、源码快照及本机 runtime 清单；字段示例和边界测试见 [`test_verified_tasks.py`](../../tests/test_verified_tasks.py)。
4. `rollout.py` 保留实际请求、工具反馈、源码摘要、提交与判分证据。`pilot.py` 是本次固定 12 题控制器，启动前要求公开规则核验回执，不是通用无限任务调度器。
5. `audit.py` 只加载同版本 tokenizer，重建每次输入，检查完整轨迹和助手目标编码；不生成、修改源码或训练。

在已准备且审核过的 Linux 任务环境中，CPU 准入入口为：

```bash
python -m one_gpu_lm.verified.admit \
  --data private/pilot-data \
  --runtime private/task-runtime.json \
  --out runs/pilot-admission-001
```

原始任务和本机运行时文件并未随仓库分发；更换自己的合法文档/代码时，需要提供自己的清单与测试。当前公开入口验证了约束，尚不是一键下载全部环境和任务的安装器。后续复用改进不会覆盖本次冻结版本。
