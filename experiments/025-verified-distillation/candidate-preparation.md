# 学生训练与四臂比较的准备状态

正式教师采集已按独立冻结的协议启动。此页对应后续入口的 CPU 检查，不表示学生已经训练，也不表示新开发集已经评分。

`one_gpu_lm.verified.candidate_data` 按整条轨迹检查来源、唯一任务、实际执行动作、审计哈希、完整编码与仓库覆盖。动作缺失、重复、非模型产生、未执行或超长都会拒绝，不把动作数量当成轨迹数量。通过后按预登记哈希顺序消费全部记录。

`one_gpu_lm.verified.candidate` 和 `candidate_watch` 实现一个候选、一个完整 epoch、8 条记录梯度累积、末尾不足 8 条的窗口仍保留。只计算目标 assistant token 的损失；记录每次反向与更新、有限梯度、参数变化、显存和硬件采样，并在保存后用训练侧输入检查重载一致性。超时或部分训练的参数不能进入评测。实际数据哈希与可执行训练协议仍待正式采集和审计完成后冻结，此时不得启动更新。

`evaluation_rollout` 只接受开发题，核对底座/学生身份与适配器哈希。四臂共享提示、输入与生成上限；提交验证只在 guard 臂启用。独立判定通过与明确提交分别记录，超过 actor 时间预算的补丁不计为预算内成功。既有最终测试不进入这个入口。

`factorial` 固定三次重复、逐题轮转四臂，并按仓库和任务做配对汇总。系统收益、参数收益与交互作用分别报告；缺少配对会阻止达标结论，已知失败和成本保留。重复运行不会被当成额外独立任务。

`evaluation` 和 `evaluation_watch` 已实现固定顺序运行、候选完整性检查、权重身份核对、切换模型成本记录和总时限监督。每次运行前检查 GPU 上只有本次后端；发现其他计算进程会保留现场并停止，不终止其他人的任务。清理只匹配本次私有 socket 与工作目录的后端。

学生训练及每次评测后端加载前，都将核对同一份模型解释器的版本记录，包括 Python、PyTorch、Transformers、PEFT、Tokenizers、Accelerate 和 Safetensors。只记录这些版本，不采集完整环境变量或连接信息。[当前观察值](preparation/model-environment-observed.json)供后续可执行协议冻结使用。版本检查用于控制依赖变化；实际重复运行的波动仍需单独报告。

`evaluation_audit` 重建模型每次实际收到的消息与规范化工具反馈，重放 token 输入，检查调用和生成上限、提交拦截的执行状态以及结果哈希。它将实际独立判定目录与冻结检查及提交补丁核对，读取已记录输出，不重新运行测试命令或模型。无法验证的分数不能进入完整配对，已知调用和 token 消耗仍然保留。

已经用 10 道人工模拟题、4 臂、3 次重复跑通 120 个 CPU 模拟实例的控制器与审计衔接。这是执行边界测试，不是真实模型能力成绩。训练和评测的可执行协议仍待真实导出数据及唯一候选的哈希可用后冻结；新开发集仍无模型评分。

`one_gpu_lm.verified.cycle_report` 已准备最终统计复算与绘图入口。它调用同一份预登记 `factorial` 规则，分别输出参数效应、系统效应、guard 下的参数效应和交互作用，保留逐题及逐仓库配对、全部已知调用/token 成本、不修改代码及错误修改、动作与结果重复波动。缺少逐运行审计标记的分数不能进入配对；没有完整配对时仍输出“未达成”和已知成本。

公开输入由 `cycle_report.public_input(...)` 从已完成的审计、三阶段控制记录、训练曲线和硬件采样中按字段提取，排除原始提示、生成文本、命令、私有训练样本标识与进程号。调用者仍需使用已获准公开的任务标识和科学规则，并在发布前检查产物。结果目录中的 `analysis-input.json` 足以在无模型、无 GPU、无私有题目的环境重算统计：

```sh
python -m one_gpu_lm.verified.cycle_report --results <结果目录> --no-figures
# 已安装 matplotlib 时，可省略 --no-figures 生成曲线。
```

输出包括 `summary.json`、`runs.csv`、`pairs.csv`、`families.csv`、训练/结果曲线及报告。三阶段卡时按流水线起止时间分别统计，包含模型切换与 CPU 工具时间；硬件采样缺失不会被记成零占用。训练损失与固定顺序累积的任务成功率分别标注，后者不作为学习曲线或 checkpoint 选择依据。当前只用本地模拟记录验证过该入口，没有发布模拟结果作为实验成绩。
