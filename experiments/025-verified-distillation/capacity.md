# 训练长度容量检查

这一步只测训练时的显存容量，不能证明编码能力提升，也不会生成训练示范。提交验证校准完成、审计通过，并公开核验本步骤的规则与实现后，才允许启动一次探测。

固定为当前已核验的 27B 底座、BF16、SDPA、LoRA rank 8、梯度检查点、batch size 1。用原创短句拼成恰好 8,192 个合成输入 token，只监督末尾 512 个 token，执行一次前向、反向和梯度裁剪。没有优化器步骤，不保存参数，不打开开发题或最终题。

为了避免只测空的优化器状态，提前按可训练参数的形状和 dtype 分配两份 AdamW moment 缓冲；同时保存 adapter 副本供不变性检查。通过条件为有限的正梯度范数、adapter 参数完全未改、冻结参数没有梯度、抽查的冻结参数值未变，以及 PyTorch 峰值 reserved memory 距设备总显存至少 8 GiB。冻结参数抽查不等于全模型逐字节复验。

独立监督进程将 worker 限制在 1,200 秒内，超时先终止，最多再用 20 秒清理进程；保留失败、峰值显存和硬件采样，不覆盖或自动重试。只在 GPU 没有其他计算进程时启动。最终以 [capacity-protocol.json](capacity-protocol.json) 的摘要和运行回执为准。

通过仍仅代表“一条最长形状的合成记录能够反向传播”。真实数据内容、持续训练碎片、完整优化器更新和非 PyTorch 显存占用仍需要在正式训练中监测；这份结果不等价于完整训练稳定性。它也不授权提前训练候选或评分新开发集。

复现入口：在已按现有项目流程核验模型与运行环境、并生成对应私有路径配置和公开核验回执后，运行 `python -m one_gpu_lm.verified.capacity_watch --root <实验目录> --protocol <capacity-protocol.json>`。未满足先决条件时程序应拒绝计算。
