# 025：唯一候选训练预登记

正式采集完成后，127 条独立完整轨迹通过逐请求重放、执行验证和无截断编码审计。它们来自 5 个仓库家族，对应 971 条实际执行的模型动作记录、60,299 个监督 token；最长编码记录为 6,922 token。原始任务、源码、轨迹及权重保持私有。

[可执行协议](candidate-protocol.json)绑定 57 个文件，包括冻结的科学规则、代码、底座身份、环境、容量检查、采集审计和实际数据。数据 SHA-256 为 `5cf7b01f18ba77d935907a96f614553fe05aca395f7cdd360bb6cbf62e8a3d37`。协议公开及 CI 成功后的回执是启动前置条件；本预登记提交时学生更新为 0，新开发集评分为 0。

| 项目 | 固定设置 |
| --- | --- |
| 底座 | Qwen/Qwen3.8-27B，固定 revision，见 [profile](candidate-profile.json) |
| 候选数量 | 1；从冻结底座加载新 LoRA，不延续此前适配器 |
| 训练 | BF16、SDPA、梯度检查点、1 个完整 epoch |
| LoRA | r=8，alpha=16，dropout=0；58,363,904 个可训练参数 |
| 优化器 | AdamW，恒定学习率 1e-5，betas=(0.9,0.999)，eps=1e-8，weight decay=0 |
| 批次与损失 | 单条动作记录；仅目标 assistant token 计算损失；8 条记录累积，保留末尾 3 条，预计 122 次更新 |
| 上限与顺序 | 8,192 token，无截断；预登记哈希顺序；种子 101；流水线最多 12 小时 |
| 检查点 | 只接受完整 epoch 结束的候选；不按开发分数选 checkpoint；超时或部分训练不合格 |

记录每条训练损失、每次梯度和更新耗时、显存及硬件采样，并核验所有记录完整消费、基础参数冻结、LoRA 参数实际变化。保存后仅用训练侧输入做 16 token 贪心重载一致性检查，不能代替任务能力评测。

通过完整性检查后，单独冻结评测协议，在同一调用和 token 预算下比较“底座/学生 × 当前流程/提交验证流程”。使用 60 道新开发题、6 个仓库家族、3 次重复，全部 720 次运行计入成本与完整性核对。主要目标与配对区间规则见 [cycle-spec.json](cycle-spec.json)，不根据训练损失宣称提升。

最终测试继续封存。此轮开发成绩不直接授权发布 ModelScope 权重；完整失败和未达标结论也需保留并公开。
