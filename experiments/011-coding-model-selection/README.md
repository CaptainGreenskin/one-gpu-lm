# 011 · 可长期使用的多语言编码模型：底座选择

状态：**Qwen3.8-27B 的首次真实权重 LoRA 链路已跑通，但微调版未通过这组回归检查，不推荐日用。** 010 的随机 7B 结果只证明其配置的容量和短步性能，不能当作以下模型的训练显存或编码能力证据；本次结果也只是短输入的工程试验。

目标是可供自己长期使用的多语言编码模型，能够在仓库内定位问题、修改多个文件、执行测试、利用错误反馈继续修复，并在长任务和中断恢复后保持目标。模型质量成为后续实验的主要验收项，训练与推理系统服务于这一目标。

候选的确切上游提交及 LICENSE、README、config 的 SHA-256 见 [candidates.json](candidates.json)。2026-11-09 已核对三组候选元数据；主线 Qwen3.8-27B 的 18 个权重分片已下载并逐项验证，[权重与元数据清单](weights-manifest.json) 固定全部文件身份。其他两个候选尚未完成本地评测。

## 第一轮实际结果与可复用入口

北京时间 2026-11-09 14:33:05–14:40:17，单张 RTX PRO 6000 上完成原始底座评测、36 步 LoRA 更新、保存重载与相同任务复测。模型实际实例化 27,356,728,560 个参数；LoRA 可训练参数 58,363,904。训练阶段 80.2 秒，峰值分配显存 52.38 GiB。实际输入只有 71–127 token，不能据此声称长上下文已验收。

18 份合成工程样例训练、9 道单独留出的简单函数题，三种语言。底座 **9/9**，微调后 **7/9**；两道题退化，无改善。它证明链路可以发现回归，不证明训练方案有收益。样本过少且简单，这些题后续只作为回归样例，不能充当高级编码或长任务排行榜。

## 单卡实施路线

27B 的 BF16 语言模型权重仅按参数量粗算约 54 GB（约 50 GiB），还需要额外的模型组件、激活、适配器与运行时空间。这是估算，不是训练显存实测。96 GB 卡优先考虑冻结主干的 LoRA，按 2K、8K、16K 逐步测训练容量；推理先测 16K、32K 的实际耗时和任务成功率。不能把原生 256K 上下文能力当作单卡能够经济地训练或服务 256K 的保证。

首先以同一评测执行系统跑未微调模型。后续仓库级阶段优先评估 [mini-SWE-agent](https://github.com/SWE-agent/mini-swe-agent) 作为执行基线；仓库测试放在隔离环境中。当前工作站没有可用的 Docker 服务，本轮函数题使用已通过检查的 bwrap 隔离；它不是仓库级多租户沙箱。已新建 Transformers 5.19.0 / PEFT 0.21.2 的独立环境并保留历史环境，具体版本与内核限制记录在结果和审计中。

多语言能力以 [SWE-bench Multilingual](https://www.swebench.com/multilingual.html) 的 300 个任务、42 个仓库、9 种语言作为一个外部评测来源，同时加入以后实际使用中积累、获得授权的仓库任务。基准测试任务和答案不得混入训练、教师示范或模型选择的反复调参数据；训练、开发与最终留出按仓库和任务来源划分。公开基准也可能已存在于上游预训练数据中，需要新的留出任务补充，不能声称绝对无污染。

任务先覆盖修复错误、增加功能、跨文件重构、补测试、修构建和多轮失败恢复。保留任务成功率、原有测试回归、每种语言表现、工具调用次数、总 token、耗时、循环失控和恢复结果。长任务再增加中断续做与上下文压缩对照；上下文窗口大小本身不算长任务验收。

后训练先使用经测试验证的合法代码修复轨迹做小规模 LoRA SFT。对教师生成的轨迹核查起始任务、工具输出、补丁与独立测试结果，只保留可信样本；不能靠教师自评“正确”筛数据。先比较原始底座与微调版，再决定是否扩数据、增加偏好训练或蒸馏到 9B。微调版需要在留出任务改善，同时监测通用编码退化。未获得有效提升的适配器不作为日用默认模型。
