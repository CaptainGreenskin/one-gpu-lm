# 041 · 从首次改码前的停滞状态接续

在 025 已审计的 164 道原始训练题中，有 22 道在工具反馈中已出现可编辑源码，随后耗尽 24 次调用且始终未改码。排除进入过 026、027、029 或 030 接手实验的 13 道，保留 9 道训练题，覆盖 5 个家族，其中 Python 7 道、JavaScript 2 道。

9 份快照均在原隔离运行时复现了前 6 次调用、工具反馈和原始源码状态。第 7 次历史请求的输入 token 已按原模板复算。每份快照另有一条在同一状态的副本上独立执行的可见回归失败记录。两种接续模板已预检全部 18 份开场输入。

两组使用同一固定版本的 27B 底座、同一快照和相同的可见操作提示。每道题相邻成对并交替先跑哪组。唯一组间变量是关闭思考或使用低档思考。计入历史开销后，每组每题剩 6 次模型调用。每组的生成 token 余额等于总额 6,144 减去历史用量。两组新调用的单次生成上限均为 2,048，输入上限为 8,192，600 秒从接续开始计时。超时请求取回原回执记账，随后结束该题。

记录首次改码、独立评分是否正确、是否在预算内通过可见验证并显式提交，以及 token、调用和耗时。合格示范要求第一次实际改码已经形成独立评分通过的最终源码，后续保持该源码、单独执行可见回归通过并实际提交，受保护文件须在全程保持完整。导出这三个执行过的动作，历史保留为输入，监督范围限于最终工具动作。首次改码的实际可见历史须保留单独确认的故障反馈，学生模板须完整编码目标。

所有 18 次尝试通过审计，且合格示范覆盖至少 6 道不同题、3 个家族后，才保留本轮训练导出。同题两组都合格时保留关闭思考组的一份。配对比较保留两组的完整成功和失败，描述这批训练状态上的结果。后续候选参数仍需通过独立开发测试及既定的发布门槛。最终测试集继续封存。[固定设计](design.json)

私有协议绑定快照、实际 tokenizer 的预检、训练来源、冻结代码和提交回执。持有原始训练记录的复现者可用以下入口核对、执行和审计。运行时只读取训练范围，原始记录、源码、权重和连接信息保留在私有目录。

PYTHONPATH=. python experiments/041-first-edit-continuation/run.py run --root . --protocol /path/to/protocol.json
PYTHONPATH=. python experiments/041-first-edit-continuation/run.py audit --root . --protocol /path/to/protocol.json
