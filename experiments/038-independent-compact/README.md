# 038 · 在新仓库复验失败摘录

**24 对已跑完并通过审计。** 旧前缀修复并提交 7/24，摘录组 9/24，新增两道、零退步，距门槛还差一道。下轮参数对照保留旧前缀。见 [曲线、匿名配对及硬件记录](results/2026-11-20/)。

037 在已观察的开发题上发现，从已有测试输出提取失败原文可能提高修复完成率。038 在四个此前未参与本项目训练或开发评测的仓库家族上复验，使用新的原始回归输出和同一个未微调的 27B 底座。

- Babel 的本地化格式、Tenacity 的本地重试行为、Simple Statistics 的数值计算和 Luxon 的日期操作。每家族六道普通功能修复题，Python 与 JavaScript 各十二道。
- CPU 入选条件为父版本重复失败两次、修复版本重复通过两次、隔离评分器通过。入选顺序依据任务 ID 指纹，模型首次输出前冻结。保留源码和测试原始许可。题目、快照、真实日志与轨迹单独存放。
- 每道题在同一基础模型上各跑一次。旧格式使用原有 2,400 字符前缀，摘录组复用 037 的 1,200 字符规则，支持 pytest 与 TAP。Luxon 的原有 Jest 断言经 TAP 报告器呈现，数值计算任务使用原生 TAP。无法解析时两臂使用同一前缀。
- 同样最多 12 次模型调用、单次 512 生成 token、每题 6,144 生成 token、单次最多 8,192 输入 token、600 秒 actor 时限。除初始失败输出外，后续反馈与隔离评分规则一致。
- 主要指标是预算内修改源代码、通过独立副本重跑公开回归并完成提交。达到净增至少三道、至少两个家族净增且最多一道退步，才认定达到复验门槛。另报告首次改码、生成与输入 token、耗时和退步。

本轮检验推理流程，参数更新数为零。复验结果将用于冻结后续参数对照所用的推理流程。底座和 LoRA 在同样流程下的增益，以及封存最终测试，属于单独发布验收。参见 [ModelScope 发布目标](../../docs/modelscope-release.md)。
