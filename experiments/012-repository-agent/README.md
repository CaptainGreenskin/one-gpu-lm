## 预先约定

具体预算、数据准入、训练配置和拒绝条件见 [protocol.json](protocol.json)。目标 24 个训练任务、8 个开发任务、8 个最终留出任务。实际数量只能在看到模型成绩前，根据控制实验与环境稳定性确定并固定；不可看分数后挑题。

实际完成 40 个任务的三组控制，**36 个准入：训练 21、开发 8、留出 7**。三个缺陷版本仍能通过已有检查，另一个触发输出上限，均提前排除。完整记录见 [admission.json](admission.json)。more-itertools 排除无关的 100 线程压力测试，p-limit 排除一个容差很窄的时间测试；这些范围调整发生在模型答题前，不能将结果称为完整上游测试套件通过。

执行端复用 mini-swe-agent 2.4.6，通过私有 Unix socket 调用本地 Transformers 后端。生成代码在无网络的 bwrap 工作区执行，依赖只读。独立控制测试已验证：第二步后退出，再用新进程恢复，消息历史、调用预算、源码哈希和评分与连续执行一致。这是可验证的工具步骤边界恢复，不代表任意执行中断都能恢复。

接口修订记录：初次启动在训练分区发现 Qwen 原生 XML 工具调用被仅接受 Bash 围栏的解析器拒绝，已停止并保留 `baseline-001`，不将其计入能力对照或训练数据。开发/留出分区当时均未运行。协议 v2 接受两种明确且唯一的 Bash 动作格式，预算、任务、评分保持一致；正式基线为 `baseline-002`。这次修订发生在看到部分训练输出后，因此不声称完整协议在任何模型输出前始终未变。

正式基线启动前，还发现 Linux `RLIMIT_NPROC` 按真实 UID 累计模型后端的线程，使原 128 上限在模型加载后阻止了 bwrap 创建命名空间。共享用户保护上限调整为 512 后，25 项 CPU / Linux 隔离 / 恢复检查在模型已加载的环境中通过。它不是单任务 cgroup 配额；该更改不改变测试断言或模型预算。

先跑底座。训练只使用训练仓库上通过验证的本地模型轨迹，或清楚标记的参考修复示范。开发与测试轨迹、答案和隐藏用例不进入训练。候选固定为低学习率、单轮 LoRA；比较相同任务、工具、模型调用次数和生成预算。

任务成功必须同时满足目标检查、声明范围内的回归检查和文件完整性检查。记录多文件修改、工具错误、耗时与 token；另做完成工具步骤后的状态保存和恢复实验。这个恢复边界不等于任意命令执行中崩溃都能无损恢复。

小规模构造任务只能作为工程与候选筛选证据；即使全部通过，也仍需真实历史 issue、更新的秘密留出、多种种子和更长任务，才能讨论广泛日用能力。失败和没有提升的结果同样公开，不以增加训练次数替代可靠验收。
